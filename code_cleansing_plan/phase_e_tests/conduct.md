# Phase E · 行为准则

## 必须(DO)

- 先打标(步骤 01)再动手;每删一批跑整体 `pytest`。
- 删 STALE/PRIVATE,合并 BEHAVIOR 中的重复;GUARDRAIL 只精简不删。
- 删完确认:每个 §1 对外契约仍有 ≥1 个测试覆盖。

## 禁止(DON'T)

- 禁止删护栏 keep-list 中的测试。
- 禁止删后降低对外行为/契约覆盖(删的只能是"测私有实现/已失效"的)。
- 禁止为合并测试引入庞大共享 fixture/工具框架(搬家不算降复杂度)。
- 禁止为了让红灯变绿而盲删失败测试——先判断是测试过时还是真回归。

## 红灯处理决策

| 测试变红原因 | 动作 |
|---|---|
| 测的是已删功能(STALE) | 删该测试 |
| 测的是被 Phase B 改名的私有实现(PRIVATE) | 删该测试 |
| 测的是对外行为,但断言文案/形状随合理改动微调 | **改测试断言**(记录原因) |
| 测的是对外行为且应保持不变 | **改代码**(这是真回归,不是测试问题) |
