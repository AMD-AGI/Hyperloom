# Phase 0 · 行为准则

## 必须(DO)

- 先建护栏、再动任何代码。Phase 0 **只新增**度量与护栏,**不删不改**业务代码。
- 如实记录环境限制(如无 GPU 跑不了全流程),宁可护栏弱一点也不伪造金标准。
- 把所有基线/金标准/keep-list **提交**,使其可被后续相位 diff。

## 禁止(DON'T)

- 禁止在 Phase 0 顺手删代码/改逻辑(那是 Phase A+)。
- 禁止把断言**私有实现细节**的测试放进护栏 keep-list(它会在 Phase B 误报红)。
- 禁止跳过本相位直接开删。

## 判定"功能一样"的优先级(后续全程沿用)

1. 护栏测试全绿(步骤 02 keep-list)。
2. CLI flag 面 / 产物键形状 与金标准一致(步骤 03)。
3. 子进程 JSON 桥 envelope 形状不变。

> 三者之外的内部行为差异**不算回归**,可放心改。
