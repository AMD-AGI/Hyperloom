# Phase C · 行为准则

## 必须(DO)

- 用 `StrReplace` 逐处精简;改完每个文件扫一眼别误删契约/坑注释。
- 多段过程注释 → 一行功能描述;docstring 已说的行内不重复。
- 每个 commit 后跑护栏:**注释改动不应改变行为**。

## 禁止(DON'T)

- 禁止用正则/`sed` 批量删 `#` 行(会误删带井号的代码、字符串、契约注释)。
- 禁止删"约束/契约/坑/反直觉意图"类注释。
- 禁止借精简之名扩写——一行能说清的不写成段。
- 禁止删 docstring 里描述对外契约(CLI flag、schema 键)的内容。

## "删 vs 留"快判

| 注释内容 | 动作 |
|---|---|
| 版本/迭代编号、历史故事 | 删 |
| 复述函数名/参数/docstring | 删 |
| 逐行"做了什么" | 删 |
| 注释掉的旧代码 | 删 |
| 为什么这样写(非显然) | 留(精简) |
| 不能改的原因 / 外部消费者 | 留 |
| 反直觉的坑/经验 | 留(精简) |

## 回归判据

护栏变红 = 误删了代码或破坏了 docstring → 立即回滚该处。注释相位**零行为变化**。
