## Port changes

- Carry the 0.29 Windows port forward onto 0.33.0. Upstream merged `csrc/libtorch_stable` back into `csrc`, removed AllSpark, consolidated the Marlin generators and added DeepSelect; the MSVC workarounds were re-applied to the new locations.
- DeepGEMM, DeepSelect, FlashKDA, QuTLASS, tml_fa4, cooperative top-k and the MiniMax all-reduce kernel are not built on Windows. Python callers check for their optional extensions; the indexer reports cooperative top-k as unavailable instead of failing.
- Replace two GCC-only bit-scan builtins (`__builtin_ctz`, `__builtin_clz`) that 0.33 added to MSVC-compiled host code with portable equivalents on MSVC only.
- The Rust frontend's new inherited-socket handoff (`Popen(pass_fds=...)`) is Unix-only. It now compiles only on Unix and reports a clear unsupported error on Windows, matching the existing HTTP listener behavior. The Rust frontend remains opt-in through `VLLM_USE_RUST_FRONTEND=1`.
- Upstream removed the `_rust_tool_parser` extension. The wheel ships only the `vllm-rs` executable; the verifier and launcher no longer expect the parser.
- Mark the sleep-mode cumem allocator unavailable on Windows. Importing it previously read `/proc/self/maps` and raised during worker shutdown; the same defect is present in 0.29.0.
- Locate torch's bundled `cudart64_*.dll` for vLLM's CUDA runtime wrapper on Windows (`VLLM_CUDART_SO_PATH` still takes precedence). Without this, 0.33's new host-registration path left the CPU offload region pageable instead of pinned.
- Re-port the Windows shared offload region, slot-mapping fallback and KV offload worker onto 0.33's segmented region and simplified slot-mapping kernel.

## Validation record

All runtime checks used the exact installed wheel outside the source tree, on RTX 3090 with `CUDA_VISIBLE_DEVICES` limited to that card.

- Exported v12 source patch: `git apply --check` passed against a clean upstream 0.33.0 checkout.
- Optimized Rust frontend: release build passed with no warnings; the executable reports `vllm-rs 0.33.0`. Transport unit tests, including the Windows unsupported-socket check, passed.
- CUDA native targets: the build completed; wheel assembly and integrity/payload validation passed, including CRCs, RECORD hashes, metadata, rewritten CuTe Python files and the Windows-specific source markers.
- Installed-wheel version, location, native module imports and expected operators passed.
- Slot-mapping fallback and shared offload region tests: 46 passed; 24 skipped because they exercise POSIX mmap/unlink semantics or require CUDA without Triton.
- Windows process and socket guards: two checks passed.
- RTX 3090 FP8 regression: automatic Marlin selection passed for a padded LM head, with and without bias; relative L2 error 0.223% and 0.276%, unchanged from 0.29.0. Capability metadata was mocked as SM120 while kernels executed on the 3090; this does not validate Blackwell execution.
- All six local cache formats passed backend write/decode checks with block remapping and ignored slots. These are cache-operation checks, not model-quality evaluations.
- Real-model serving: Qwen3.5-9B GPTQ, Triton attention, compilation and CUDA graphs enabled. Ordinary and streaming chat returned the same correct answer.
- CPU-ARC offload: identical generated token IDs after clearing the GPU prefix cache, with 1,056 cached tokens restored from a 1,452-token prompt. The CUDA runtime fix was confirmed with a pinned-region restore on the Python 3.14 build and a direct host-registration check on this build.

Not validated: filesystem offload modes (their code changed little and shares the CPU worker path), the multi-process `vllm serve` socket-handoff path, sleep mode (unsupported on Windows), other model families and Blackwell hardware. Test processes exited and released the RTX 3090.

## Build notes

Use an isolated checkout and virtual environment. Load the Visual Studio 2022 x64 build environment, then put the virtual environment, CUDA 13.0, Git (including `usr/bin` for `patch.exe`) and Rust tools on a short `PATH`. Pass vendor source paths to CMake with forward slashes.

Set `TORCH_CUDA_ARCH_LIST=7.5;8.6;8.9;12.0`, `VLLM_TARGET_DEVICE=cuda`, `CMAKE_BUILD_TYPE=Release`, `VLLM_DISABLE_SCCACHE=1` and `SETUPTOOLS_SCM_PRETEND_VERSION=0.33.0`. This build uses `MAX_JOBS=8`. Set `OPENSSL_SRC_PERL` to a complete Perl installation and `PROTOC` to the protobuf compiler for the Rust frontend.

Build the optimized Rust executable first with `.venv\Scripts\python.exe tools\build_rust.py --release` and `VLLM_RS_BUILD_VERSION=0.33.0`, then compile CUDA with `.venv\Scripts\python.exe setup.py build_ext --inplace -v`. The executable must exist when `setup.py` starts so it is reused instead of rebuilt in debug mode.

For assembly, set `VLLM_USE_LOCAL_PRECOMPILED=1`, `VLLM_SKIP_PRECOMPILED_VERSION_SUFFIX=1` and `VLLM_VERSION_OVERRIDE=0.33.0`, then run `uv build --wheel --no-build-isolation`. Validate the archive before installing that exact wheel outside the source tree.
