# vLLM 0.27.1 Native Windows (CUDA 13.0 / Python 3.13)

This release updates the native Windows build to upstream vLLM 0.27.1 and
the matching PyTorch 2.13.0+cu130/CUDA 13.0 stack. It does not require WSL,
Docker, or a Linux virtual machine.

## Highlights

- CPython 3.13 native Windows wheel built with CUDA 13.0 Update 2.
- CUDA targets for SM 7.5, 8.6, 8.9, and 12.0 (RTX 20/30/40/50 families).
- Stable-libtorch CUDA/MoE extensions, FlashAttention 2, optimized Rust
  frontend, and Rust tool parser included in the wheel.
- Ten KV-cache formats: six local Multi-TurboQuant methods and four upstream
  TurboQuant variants.
- Experimental opt-in CPU LRU/ARC and persistent filesystem/NVMe LRU/ARC
  prompt-KV tiers.
- Current source delta published as `vllm-windows-v10.patch`, based exactly on
  upstream tag v0.27.1.
- Integrated launcher request annotations remain resolvable by FastAPI under
  Python 3.13, so JSON chat/embedding bodies are routed correctly.

The required runtime is PyTorch 2.13.0+cu130, not a mixed Torch/CUDA build.
Use `install.bat` to provision the pinned Python, Torch, Triton, vLLM, and
Multi-TurboQuant versions together.

## Validation

The final wheel was installed directly into a clean CPython 3.13 environment
and tested on an RTX 3090 with the local
`Qwen3.5-9B-abliterated-GPTQ-4bit` model:

- Three OpenAI-compatible API requests completed without errors.
- The integrated Windows launcher returned HTTP 200 from `/health` and
  `/v1/chat/completions`; its real request used 17 prompt and 24 generated
  tokens and completed in 2.918 seconds.
- All six local Multi-TurboQuant formats passed direct GPU cache write/decode
  smoke tests with the pinned companion wheel installed.
- Prefix caching recorded 1,056 hits from 2,952 prompt tokens (35.77%).
- vLLM reported 11.52 GiB KV capacity, 208,896 KV tokens, and 51x estimated
  4,096-token concurrency at the tested 0.80 GPU-memory setting.
- CPU LRU, forced filesystem eviction/restore, and fresh-process persistent
  reuse each restored 1,056 of 1,452 prompt tokens with exact output tokens.
- Focused Windows source regressions: 80 passed, one expected platform skip,
  zero failed.
- Repository contracts: 24 passed. Wheel payload, CRC, metadata, and RECORD
  validation passed.

The RTX 3090 was returned to its idle state after testing. Results are for the
listed model and configuration, not universal performance guarantees.

## Known boundaries

- **Post-release issue #16:** mixed FP8/NVFP4 models can fail at startup on
  Blackwell because backend selection allows an omitted CUTLASS FP8 kernel.
  The reporter confirmed `unsloth/Qwen3.8-27B-NVFP4` serving with CUDA graphs
  on an RTX PRO 5000 Blackwell using the
  [Marlin setting and two-line Python fix](https://github.com/aivrar/vllm-windows-build/blob/master/docs/troubleshooting.md#blackwell-fp8-nvfp4).
  These steps require no wheel rebuild, but are not included in the published
  wheel or installer and do not enable native FP4 acceleration.
- CPU/filesystem KV tiering remains experimental and disabled by default.
- Filesystem tiers require an explicit cache directory and do not impose an
  automatic disk quota.
- Direct `.gguf` input is not supported by the launcher; use Hugging Face
  model format with compatible safetensors/AWQ/GPTQ weights.
- A few SM120-only CUTLASS FP8/NVFP4 specializations whose aligned by-value
  parameters are incompatible with the Windows x64 ABI are omitted. This does
  not remove general Blackwell support.

See the [full build and validation record](https://github.com/aivrar/vllm-windows-build/blob/master/docs/v0.27.1-build-candidate.md)
for the exact toolchain, package contents, and measurements.
