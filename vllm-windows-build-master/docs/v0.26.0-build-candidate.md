## Windows changes carried into v0.26.0

- Windows build/runtime patches were ported from the previous release.
- Linux-only QuTLASS, cooperative TopK, DeepGEMM, and CuTe FA4 targets are
  skipped or guarded on Windows.
- The hybrid-KV block-table fallback is fixed for non-Triton paths.
- The Rust mock-engine IPC wait no longer calls UnixStream on Windows.
- Wheel assembly can reuse locally compiled `.pyd` files with
  `VLLM_USE_LOCAL_PRECOMPILED=1`; it never downloads an upstream Linux wheel in
  that mode.

## RTX 20xx / issue #14

The launcher now accepts:

```text
--attention-backend TRITON_ATTN
--kv-cache-dtype float16
--block-size 32
--turing-compat
```

`--turing-compat` applies the first three settings and enables eager execution.
Following the issue #14 RTX 2080 Ti test, it also defaults to 0.89 GPU memory
utilization, one sequence, and 2,048 batched tokens. Explicit values still win.
The default context remains 8,192. This avoids the negative KV-cache budget
produced by the original general-purpose 0.6/64 defaults on an 11-GB card.

`launch.bat` also sets `CUDA_DEVICE_ORDER=PCI_BUS_ID` (when not already set),
`PYTHONUTF8=1`, and `PYTHONIOENCODING=utf-8`. This makes `--gpu-id` match the
order shown by `nvidia-smi` and prevents the vLLM startup banner from producing
cp1252 logging errors.

## Validation performed

1. The six CUDA/native extensions and two Rust artifacts imported from the
   installed wheel; `vllm.exe --help` completed successfully.
2. A direct `vllm serve` run on the RTX 3090 loaded local Qwen3-14B AWQ with
   Marlin and `TRITON_ATTN`, then returned HTTP 200 for a chat completion.
3. The integrated Windows launcher loaded the same model on the RTX 3060 with
   `--turing-compat` and returned an HTTP 200 chat completion.
4. Launcher source compilation, option forwarding, release-contract tests, and
   Windows runtime guard tests passed.
5. The issue #14 reporter installed the published wheel and loaded
   `cyankiwi/Qwen3.5-9B-AWQ-4bit` on an RTX 2080 Ti with the Turing profile.
   Final request-level confirmation remains pending.
6. The follow-up verifier, Turing defaults, override precedence, and GGUF
   preflight passed 27 repository tests. The existing wheel's content, RECORD,
   size, and SHA-256 were revalidated unchanged.

The Qwen3.5-9B GPTQ directory remains a separate compatibility issue: its
checkpoint exposes a Transformers `Qwen3_5TextConfig` where this vLLM build
expects the vLLM `Qwen3_5Config`. That failure is model/config compatibility,
not evidence that the native wheel or SM 7.5 code is missing.
