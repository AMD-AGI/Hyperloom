# v_mfma_i32_16x16x64_i8

INT8 matrix fused multiply-add, 16x16 output tile, K=64. Integer MFMA for quantized inference workloads. Produces INT32 accumulation.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_i32_16x16x64_i8` |
| Tile Shape | 16 rows x 16 cols, K=64 |
| Input Type | INT8 (packed in VGPRs) |
| Output Type | INT32 (accumulated in AGPRs) |
| Latency | Not measured |
| Issue Rate | Not measured |
| FLOPs | 16 * 16 * 64 * 2 = 32,768 integer OPs |
| Measured CPI | ~5.4 shader cycles (isa-bench, raw FCLK CPI = 0.922) |

### CPI Note

The measured throughput CPI of ~5.4 shader cycles is surprisingly low, possibly indicating the INT8 pipeline is faster than BF16/FP8 pipelines, or the benchmark methodology differs. This value should be validated independently before relying on it for scheduling.

---

## Output Layout

Not measured. Expected to follow the same 16x16 column-major layout as other 16x16 MFMA instructions:

```
Lane L (0..63) has 4 AGPRs: a[k] = C[(L/16)*4 + k, L%16]   for k=0..3
```

## NOP Requirements

Not measured. Expected to follow the same hazard rules as other MFMA instructions on gfx950:

| Transition | Expected Wait |
|------------|---------------|
| `s_waitcnt` -> this MFMA | 0 NOPs |
| VALU write -> this MFMA (same src VGPR) | 2 NOPs |
| Last MFMA -> `v_accvgpr_read_b32` | 64 NOPs (conservative) |

## Known Bugs / Gotchas

1. **Limited empirical validation**: This instruction has only been benchmarked for throughput CPI. Output layout, co-execution window, and NOP requirements have not been empirically validated.

2. **Same accum_offset/AGPR aliasing bugs as all MFMA instructions.**
