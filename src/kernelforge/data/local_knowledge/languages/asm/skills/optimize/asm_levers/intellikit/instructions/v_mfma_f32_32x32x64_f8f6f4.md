# v_mfma_f32_32x32x64_f8f6f4

MI355X-native FP8/FP6/FP4 matrix fused multiply-add, 32x32 output tile, K=64. The large-tile FP8 MFMA for MI355X. Delivers 131,072 FLOPs per instruction. Used in dot_scaled grouped GEMM workloads.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f32_32x32x64_f8f6f4` |
| Tile Shape | 32 rows x 32 cols, K=64 |
| Input Type | FP8/FP6/FP4 (selected by CBSZ/BLGP) |
| Output Type | FP32 (accumulated in AGPRs) |
| Latency | ~32 cycles |
| Issue Rate | ~32 cycles |
| FLOPs | 32 * 32 * 64 * 2 = 131,072 |
| Measured CPI | ~63.3 shader cycles (isa-bench, raw FCLK CPI = 3.75) |

### CPI Note

The isa-bench measured CPI of ~63.3 is approximately 2x the expected 32-cycle issue rate. This suggests the benchmark may have had accumulator dependencies (only one accumulator set) or the actual issue rate for this variant is 64 cycles. Cross-reference with the 16x16x128 variant (31.6 CPI, matches 32-cycle issue rate). The doubling to ~63 CPI for the 32x32 variant is consistent with each variant's relative pipeline depth.

---

## Output Layout (Column-Major)

Same 32x32 column-major layout as v_mfma_f32_32x32x16_bf16:

```
Half h = l / 32         (0 or 1)
Lane l: N = l % 32      (column index, 0..31)

VGPR k (0..15): M = h*4 + (k%4) + (k/4)*8
```

16 AGPRs per instruction output.

## Co-Execution Window

| Cycle Range | Activity |
|-------------|----------|
| 0-7 | Reads A, B, D operands. No co-execution. |
| 8-11 | Co-exec: TEX, LDS. VALU not available until cycle 12. |
| 12-31 | Full co-exec: TEX, LDS, ALU0, LD_SCALE. |
| 32+ | Can issue next MFMA. |

Note: If actual issue rate is 64 cycles as suggested by isa-bench, the co-execution window extends to cycles 12-63, providing substantial scheduling freedom.

## NOP Requirements

| Transition | Required Wait |
|------------|---------------|
| `s_waitcnt` -> this MFMA | **0 NOPs** |
| VALU write -> this MFMA (same src VGPR) | **2 NOPs** (s_nop 1 x 2) |
| This MFMA -> another MFMA (diff AGPR dest) | **0 NOPs** |
| Last MFMA -> `v_accvgpr_read_b32` | **64 NOPs** (s_nop 15 x 4) |
| `v_accvgpr_write_b32` -> this MFMA (same AGPR) | **1 NOP** (s_nop 0) |

Same format selection as v_mfma_f32_16x16x128_f8f6f4:

| CBSZ[2:0] | A Format | BLGP[2:0] | B Format |
|-----------|----------|-----------|----------|
| 0 | FP8 (E4M3) | 0 | FP8 (E4M3) |
| 1 | BF8 (E5M2) | 1 | BF8 (E5M2) |
| 2 | FP6 (E3M2) | 2 | FP6 (E3M2) |
| 3 | FP6 (E2M3) | 3 | FP6 (E2M3) |
| 4 | FP4 (E2M1) | 4 | FP4 (E2M1) |

Empirically validated: `cbsz:1` on 32x32x64 for wgrad GEMM.

**FNUZ correction**: Same as 16x16x128 -- apply 0.25x correction factor for FNUZ data via `tl.dot_scaled`.

## Known Bugs / Gotchas

1. **16 AGPRs per block**: Same high register pressure as 32x32x16_bf16. A 4x4 grid needs 256 AGPRs.

2. **8 VGPRs per source**: Same elevated source register requirement as 16x16x128_f8f6f4.

3. **Source read extends to cycle 11**: Cannot overwrite source VGPRs until cycle 12.

4. **CPI may be 2x issue rate**: isa-bench measured ~63 CPI which is 2x the expected 32 cycles. May indicate the actual pipeline depth is 64 cycles for this variant, or a benchmark artifact. Treat with caution.

5. **Same accum_offset/AGPR aliasing bugs as all MFMA instructions.**

---

## Use Cases

- **dot_scaled grouped GEMM (wgrad)**: Variable-K wgrad across expert groups. The `tl.dot_scaled` Triton intrinsic maps to this opcode.
- **Large-tile FP8 GEMM**: When 32x32 tile shape is preferred for higher arithmetic intensity.
- **1.74x speedup over legacy**: The MFMA opcode upgrade from fp8_bf8 to f8f6f4 with 32x32 tiles gives 1.74x on wgrad (the single biggest grouped GEMM optimization).

## vs 16x16x128 Comparison

| Property | 16x16x128_f8f6f4 | 32x32x64_f8f6f4 |
|----------|-------------------|-------------------|
| FLOPs/inst | 65,536 | 131,072 |
| AGPRs per block | 4 | 16 |
| Measured CPI | ~31.6 | ~63.3 |
| FLOPs/cycle | ~2,074 | ~2,070 |
| Register pressure | Lower | Higher |
| Use case | Persistent FWD/DGRAD | Wgrad, large tiles |

Both variants have nearly identical compute density. Choose based on tile shape requirements and register budget.
