# v_mfma_f32_16x16x16_bf16

Legacy BF16 matrix fused multiply-add, 16x16 output tile, K=16. Half the throughput of the XDL2x v_mfma_f32_16x16x32_bf16. Present on both MI300X (gfx942) and MI355X (gfx950). On gfx950, prefer the 16x16x32 variant which gives 1.87x throughput.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f32_16x16x16_bf16` |
| Tile Shape | 16 rows x 16 cols, K=16 |
| Input Type | BF16 (packed pairs in VGPRs) |
| Output Type | FP32 (accumulated in AGPRs) |
| Latency | ~16 cycles |
| Issue Rate | Not measured (use 16x16x32 instead) |
| FLOPs | 16 * 16 * 16 * 2 = 8,192 |
| Measured CPI | Not measured (isa-bench does not include this opcode) |

---

## Output Layout (Column-Major)

Same column-major layout as v_mfma_f32_16x16x32_bf16:

```
Lane L (0..63) has 4 AGPRs: a[k] = C[(L/16)*4 + k, L%16]   for k=0..3
```

---

## Operand Requirements

| Operand | Register | Count | Constraint |
|---------|----------|-------|------------|
| Src0 (A) | VGPRs or AGPRs | 4 | **Accepts both VGPRs and AGPRs** (unlike XDL2x variants) |
| Src1 (B) | VGPRs or AGPRs | 4 | **Accepts both VGPRs and AGPRs** |
| Src2/Dst (C/D) | AGPRs | 4 | Accumulator input/output |

Note: This is the only BF16 MFMA variant where sources can be AGPRs. The XDL2x (16x16x32) variant requires VGPR sources only.

---

## Co-Execution Window

Not measured. Expected to be similar to the 16x16x32 variant but with half the compute per instruction.

---

## NOP Requirements

| Transition | Required Wait |
|------------|---------------|
| `s_waitcnt` -> this MFMA | **0 NOPs** |
| VALU write -> this MFMA (same src VGPR) | **2 NOPs** (s_nop 1 x 2) |
| This MFMA -> another MFMA (diff AGPR dest) | **0 NOPs** |
| Last MFMA -> `v_accvgpr_read_b32` | **32 NOPs** (s_nop 15 x 2) |
| `v_accvgpr_write_b32` -> this MFMA (same AGPR) | **1 NOP** (s_nop 0) |

Note: The MFMA drain for legacy (non-XDL2x) 16x16 opcodes is 2x s_nop 15 (32 cycles), NOT 4x as required for XDL2x opcodes. This distinction matters.

---

## Known Bugs / Gotchas

1. **Half throughput vs 16x16x32**: Only 8,192 FLOPs vs 16,384. On MI355X, always prefer the 16x16x32 variant unless you specifically need AGPR source operands.

2. **BWD attention uses 480 of these**: BWD attention kernels using this opcode for 5-GEMM decomposition should upgrade to 16x16x32 for 1.87x throughput.

3. **Same accum_offset/AGPR aliasing bugs as all MFMA instructions.**

4. **~64 cycles latency reported in some contexts**: ~64 cycles has been observed in BWD attention, possibly including pipeline overhead or confusion with the full drain time.

## Use Cases

- **MI300X backward compatibility**: Code targeting both MI300X and MI355X.
- **BWD attention (legacy)**: Used in 5-GEMM BWD attention decomposition (480 MFMAs per kernel).
- **AGPR source requirement**: Only BF16 MFMA that accepts AGPR sources, useful for AGPR-to-AGPR computation chains.
- **Recommendation**: On MI355X, migrate to v_mfma_f32_16x16x32_bf16 for 1.87x throughput improvement.
