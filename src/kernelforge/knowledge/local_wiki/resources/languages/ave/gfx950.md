# gfx950 raw-buffer and synchronization rules

## Applicability

These invariants were used by the AveLang MoE history suite on MI350/MI355 (gfx950). Apply them when changing raw-buffer addressing, LDS DMA or coherence scopes on that target. Verify instruction bindings in the selected AveLang source before transferring them to another architecture or compiler version.

## Addressing and bounds

Keep wave-uniform bases in `soffset` (SGPR) and lane-varying displacements in `voffset` (VGPR). The descriptor range check covers the instruction offset plus `voffset`, not `soffset`. A base advancing through `soffset` must remain inside the allocation by construction.

Raw-buffer bounds are exclusive byte counts. Out-of-range loads return zero; out-of-range stores and atomics are discarded. Apply an invalid-lane sentinel to the final address: `0xFFFFFFFF + k * 128` wraps to a small, potentially misaligned in-bounds address. If a cached base can be invalid, use `al.select(base != 0xFFFFFFFF, base + k * 128, al.convert(0xFFFFFFFF, al.u32))`. Correct output alone cannot detect wasted invalid-lane memory traffic; measure padded cases too.

## LDS DMA ownership

`raw_buffer_load_x{1,4}_lds(resource, lds, bytes, voffset, soffset, lds_byte_offset, aux)` takes a wave-uniform LDS byte offset. Hardware adds `lane * bytes`: x4 writes at `lds_byte_offset + lane * 16`, x1 at `lds_byte_offset + lane * 4`.

Every active lane writes its destination even when the source is out of bounds, in which case it writes zeros. Reserve a disjoint destination for every active lane of every participating wave. Mask lanes or waves with no destination using an `if` predicate; an out-of-range source does not disable the LDS write. Complete DMA with `s_waitcnt(0, 0, 0)` and a workgroup barrier before another thread reads it. Neither operation can repair overlapping destinations.

## Scope and completion

On gfx950, raw-buffer `aux` bits are SC0=1, NT=2, SWZ=8 and SC1=16. For loads/stores, scopes are wave=0, group=1, device=16 and system=17; NT is an independent hint, so 18 means device scope plus NT. Atomics interpret these differently: 16 selects system scope and 0 device scope; the intrinsic supplies the return-value bit, so do not add SC0 yourself.

A signal poll must bypass stale CU-cache contents using device/system scope (16 or 17); the history suite uses 17. Reducing data-traffic scope is not permission to weaken polling scope. Scope bits do not complete memory operations or replace producer/consumer ordering. Check waits, thread participation and arena lifetimes separately when changing cache policy or removing a barrier.
