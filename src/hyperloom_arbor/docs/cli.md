# Arbor's commands and their parameters

Every command takes its parameters as flags, or as one JSON or YAML document, a payload. The two are the same
parameters: the payload becomes the command's own flags, and the command's own parser reads them. The tables below are
generated from those parsers, and so is the payload's JSON Schema
([`schema/arbor-cli-payload.schema.json`](schema/arbor-cli-payload.schema.json)). A test fails when either is stale;
`python3 -m arbor schema --write` regenerates both.

## The payload

```bash
python3 -m arbor run --payload run.yaml          # the command on the line, its parameters in the file
python3 -m arbor --payload run.yaml              # the command in the file (command: run)
python3 -m arbor run --payload - < run.json      # from stdin
python3 -m arbor.directions --payload split.yaml # action: generate | split
python3 -m arbor schema [<command>]              # the JSON Schema, every command's or one; --markdown for the tables
```

```yaml
arbor_payload: 1          # the format's version: required
command: run              # required unless the command line names it; must match when both do
config: /work/b01/config.json
review_gate: false        # true: --review-gate, false: --no-review-gate, null or absent: the default
split: loop
```

- **Keys are the parameters' names:** the long flag without `--`, with `_` for `-` (`max_iters`, `review_gate`,
  `opt_objective`). A positional or a sub-command is a key too (`action`, `cmd`), and the sub-command's parameters sit
  beside it.
- **Exact types:** a string, an integer, a number, a boolean, or one of the parameter's choices. `"3"` for an integer is
  refused, not converted. A null value is the default.
- **Strict:** an unknown key, a hidden parameter, another command's or another action's key, or a wrong type exits 2,
  naming the key and what the command takes. A payload never drops a key.
- **The payload stands where the flags stand:** a parameter wins over its environment variable (`ARBOR_SPLIT`,
  `ARBOR_REVIEW_GATE`, `ARBOR_SKILL_CONFLICTS`, `ARBOR_OPT_OBJECTIVE`), which wins over the config's key. A flag on the
  same command line as `--payload` wins over the payload's key; two sides of one exclusive pair are refused.
- **`run` with `dry_run: true`** is `run --dry-run`, which admits the dry run's `seed`.
- **Paths:** relative ones resolve against the working directory, as on the command line. `config` is a path to the
  campaign config, which a resume, the review gate and a person read again.
- **The record:** a campaign's start writes `<session>/invocation.json`: the command, its effective parameters,
  which came from the payload, the payload's path and sha256, and Arbor's version.
- **For a caller:** `python3 -m arbor version --json` has `interfaces.cli` 5 or more, and a `payload` section (the
  format's version, the formats, the commands, the schema's id), once this checkout takes a payload.

### `run`

`python3 -m arbor run`

| Key | Flag | Type | Default | Required | Meaning |
| --- | --- | --- | --- | --- | --- |
| `config` | `--config` | string |  | yes | Campaign config JSON |
| `split` | `--split` | `loop` \| `processes` \| `workers` | loop, or ARBOR_SPLIT when set |  | loop: the master and its workers in this process (the default); processes: each side as its own command, python3 -m arbor master, then worker --order, in turn (also ARBOR_SPLIT=processes, as a host that launches arbor run passes it); workers: the master deals its map to several workers at once, one per slot of the config's workers block, and integrates what they kept (arbor/dealer.py) |
| `max_iters` | `--max-iters` | integer | `0` |  | 0 = run until target or STOP file |
| `cooldown` | `--cooldown` | integer | `30` |  | Seconds between iterations |
| `opt_objective` | `--opt-objective` | string |  |  | optimize this metric in place of the pack's: a name ("P50 interactivity", "total throughput") or a bench key with its direction ("tpot_p50:min"). Also ARBOR_OPT_OBJECTIVE, or "opt_objective" in the config; arbor/objective.py |
| `allow_pack_results` | `--allow-pack-results` | boolean | `false` |  | accept a results/ directory inside the pack (refused by default: a pack is the contract every campaign of its kind shares, so results kept in it reach every campaign that uses the pack, where an agent may read another model's, node's or image's numbers as evidence about its own; they also grow the pack and its repository) |
| `review_gate` | `--review-gate` / `--no-review-gate` | boolean or null |  |  | true: --review-gate, a fresh session waits for a human's approval before it runs anything (the default; arbor/review.py); false: --no-review-gate, start without the review (also ARBOR_REVIEW_GATE=0, or "review_gate": false in the config); null or absent: the default |
| `skill_conflicts` | `--skill-conflicts` | `pause` \| `merge` |  |  | two loaded skills that write the same thing: pause for a person to decide (the default), or merge them with an agent, without a pause (also ARBOR_SKILL_CONFLICTS, or "skill_conflicts" in the config; arbor/conflicts.py) |
| `dry_run` | `--dry-run` | boolean | `false` |  | the loop on synthetic numbers, with no GPU and no agent (arbor run --dry-run); it takes seed, and its own defaults for max_iters and cooldown |
| `seed` | `--seed` | integer | `42` |  | the synthetic numbers' random seed (with dry_run: true) |
