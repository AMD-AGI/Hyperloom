# Arbor's host interface

For anyone who launches or hosts Arbor: a scheduler, a cluster job, or a host that runs Arbor as one of its components
([component-mode.md](component-mode.md), [hosts.md](hosts.md)).

The contract is generated from the code. `python3 -m arbor interface --json` prints it, and the tables below are
rendered from it (`python3 -m arbor interface --write`). Read it from the Arbor you run: it says what that Arbor does.

- **Versions.** `arbor.host/<major>.<minor>`, also in `version --json` (`interface`). An additive change raises the
  minor, a breaking one the major, and a test fails when the contract changes and its version does not. Version 1 is
  the interface hosts integrated against before it was published (`version --json`'s `component` 1 to 5); 2.0
  publishes it as it is.
- **Records.** Each file Arbor writes for a host carries `schema`, its schema's id, and `arbor`, the Arbor that wrote
  it (`version`, and `commit` when Arbor is its own git checkout). The schemas are in [`schema/host/`](schema/host/).
  `python3 -m arbor interface --check <file>` checks one record (exit 1, saying what is wrong);
  `arbor.interface.validate` does it in the standard library alone.
- **Ends.** Read a run's end by its outcome, not by its exit code alone: an `aborted` run exits 0 and is broken, and
  a paused one exits 76 and must not be started again by itself. The table says what a host should do for each.
- **Not in it yet.** Messages are files a person or a host writes (STOP, PAUSE, review.json, conflicts.json); a
  standalone run writes no exit record and no heartbeat; the journal has no sequence numbers.

### The channels

| Channel | Today |
| --- | --- |
| start | a command (`commands`) with --config or --payload; a host's config carries `mode: component` and the component block (`config.component_keys`). A refused start exits 2. A session directory that is setgid and group-writable is a group's: the run's umask keeps group-write, so another account of the group can continue it. |
| messages_in | files in the session, read at a pass boundary or while the start waits: STOP (stop after the iteration in flight), PAUSE (`arbor pause`), review.json (`arbor review`), conflicts.json (`arbor conflicts`); SIGTERM stops a run at once. |
| events_out | the journal, one JSON object a line (`journal`); a host's callbacks (component.callbacks), called with each event; heartbeat.json in component mode. |
| results_out | the session's records (`records`): a KEEP snapshot per KEEP in component mode, the ledger, the map, the roles' records, the objective. |
| end | the exit code and, in component mode, the exit record (`exit`); a refused start's record. |

### How a run ends

| Outcome | Means |
| --- | --- |
| `finished` | the run ended as it should: take its results |
| `handed_over` | the run did its part and hands the next step on: to the host, a worker or a successor job |
| `broken` | the harness stopped itself: what it kept stands, but it did not finish; never read it as finished |
| `needs_person` | a person decides before anything continues |
| `resumable` | start the same command again, a bounded number of times: it continues the same session |
| `paused` | someone paused it: it continues when asked, never on its own |
| `refused` | it never started: fix what it names, and never start it again unchanged |
