# v_mfma_f64_16x16x4_f64

FP64 (double-precision) matrix fused multiply-add, 16x16 output tile, K=4. The primary FP64 MFMA instruction. Very low K per instruction compared to lower-precision variants.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f64_16x16x4_f64` |
| Tile Shape | 16 rows x 16 cols, K=4 |
| Input Type | FP64 (double precision) |
| Output Type | FP64 (accumulated in AGPRs) |
| Latency | Not measured |
| Issue Rate | Not measured |
| FLOPs | 16 * 16 * 4 * 2 = 2,048 FP64 FLOPs |
| Measured CPI | ~15.6 shader cycles (isa-bench, raw FCLK CPI = 2.688) |

### CPI Note

isa-bench gfx950 DGEMM notes: gfx950 adds +1 cycle penalty vs gfx942 for most XDL MFMA operations. DGEMM 16x16 jumps from 9 to 17 cycles (gfx942 -> gfx950). The measured ~15.6 CPI is in the right neighborhood.

## Known Bugs / Gotchas

1. **gfx950 penalty vs gfx942**: DGEMM 16x16 jumps from 9 to 17 cycles. This is a significant regression from MI300X.
2. **K=4 means many iterations**: Each instruction only processes K=4, so DGEMM requires many more MFMAs per K-step than BF16/FP8 variants.
3. **No empirical validation beyond throughput CPI.**

## Use Cases

- **HPC double-precision GEMM**: Scientific computing, CFD, linear algebra.
- **FP64 matrix operations**: Where double precision is required.
- **Note**: MI355X prioritizes lower-precision formats (FP8/BF16). FP64 performance is not the primary design target.
