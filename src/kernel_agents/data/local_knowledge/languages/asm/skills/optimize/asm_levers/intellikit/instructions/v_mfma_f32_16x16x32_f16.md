# v_mfma_f32_16x16x32_f16

FP16 matrix fused multiply-add, 16x16 output tile, K=32. Identical tile shape and pipeline behavior to the BF16 variant but operates on IEEE FP16 inputs. Used in FP16 GEMM and GEMV decode paths.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f32_16x16x32_f16` |
| Tile Shape | 16 rows x 16 cols, K=32 |
| Input Type | FP16 (packed pairs in VGPRs) |
| Output Type | FP32 (accumulated in AGPRs) |
| Latency | 16 cycles |
| Issue Rate | 8 cycles |
| FLOPs | 16 * 16 * 32 * 2 = 16,384 |
| Measured CPI | ~15.6 shader cycles (isa-bench, raw FCLK CPI = 1.016) |

---

## Output Layout (Column-Major)

Identical to v_mfma_f32_16x16x32_bf16:

```
Lane L (0..63) has 4 AGPRs: a[k] = C[(L/16)*4 + k, L%16]   for k=0..3

  lane_row = L % 16    -> column index (0..15)
  col_group = L / 16   -> row group (0..3)
  4 AGPRs hold 4 consecutive ROWS in the same column
```

## Operand Requirements

| Operand | Register | Count | Constraint |
|---------|----------|-------|------------|
| Src0 (A) | VGPRs | 4 | Must be VGPRs, NOT AGPRs |
| Src1 (B) | VGPRs | 4 | Must be VGPRs, NOT AGPRs |
| Src2/Dst (C/D) | AGPRs | 4 | Accumulator input/output |

---

## Co-Execution Window

Identical to v_mfma_f32_16x16x32_bf16:

| Cycle Range | Activity |
|-------------|----------|
| 0-7 | Reads A, B, D operands. No co-execution. |
| 8-11 | Free. Co-exec: TEX, LDS, ALU0. |
| 12-15 | Free. Co-exec: TEX, LDS, ALU0, LD_SCALE. |
| 16+ | Can issue next MFMA. |

---

## NOP Requirements

Same hazard rules as all XDL2x 16x16 MFMA instructions:

| Transition | Required Wait |
|------------|---------------|
| `s_waitcnt` -> this MFMA | **0 NOPs** |
| VALU write -> this MFMA (same src VGPR) | **2 NOPs** (s_nop 1 x 2) |
| This MFMA -> another MFMA (diff AGPR dest) | **0 NOPs** |
| Last MFMA -> `v_accvgpr_read_b32` | **64 NOPs** (s_nop 15 x 4) |
| `v_accvgpr_write_b32` -> this MFMA (same AGPR) | **1 NOP** (s_nop 0) |

---

## Known Bugs / Gotchas

1. All the same bugs/gotchas as v_mfma_f32_16x16x32_bf16 apply (accum_offset, AGPR aliasing, column-major output, etc.).

2. **FP16 vs BF16 precision**: FP16 has higher mantissa precision (10 bits vs 7 for BF16) but smaller dynamic range (exponent 5 bits vs 8 for BF16). For training workloads, BF16 is preferred for its dynamic range. For inference with pre-scaled weights, FP16 can be adequate.

## Use Cases

- **FP16 GEMV decode**: Used in v_mfma_f32_16x16x32_f16 path for GEMV decode in DeepSeek-V4-Flash inference.
- **FP16 GEMM**: Direct replacement for BF16 variant when inputs are IEEE FP16.
- **Mixed-precision inference**: FP16 weights with FP32 accumulation.
