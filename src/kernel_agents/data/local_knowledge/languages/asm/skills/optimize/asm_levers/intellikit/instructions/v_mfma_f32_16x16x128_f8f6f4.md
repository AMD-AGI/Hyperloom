# v_mfma_f32_16x16x128_f8f6f4

MI355X-native FP8/FP6/FP4 matrix fused multiply-add, 16x16 output tile, K=128. The primary FP8 MFMA for MI355X, delivering 8x the FLOPs per instruction of the legacy fp8_bf8 variant. Switching from legacy to this opcode is the single biggest grouped GEMM optimization (1.67-1.76x speedup).

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f32_16x16x128_f8f6f4` |
| Tile Shape | 16 rows x 16 cols, K=128 |
| Input Type | FP8/FP6/FP4 (selected by CBSZ/BLGP) |
| Output Type | FP32 (accumulated in AGPRs) |
| Latency | 32 cycles (some sources report 48, see note) |
| Issue Rate | 32 cycles |
| FLOPs | 16 * 16 * 128 * 2 = 65,536 |
| Measured CPI | ~31.6 shader cycles (isa-bench, raw FCLK CPI = 1.906) |

### Latency Disagreement

- **Empirical measurement**: 32-cycle issue rate (isa-bench CPI ~31.6).
- **Some contexts** report 48 cycles total latency, with co-exec window cycles 8-47 = 40 cycles, next MFMA at cycle 32. This suggests: 32-cycle issue rate but 48-cycle result latency.
- **Interpretation**: Issue rate is 32 cycles. Pipeline result latency may be up to 48 cycles. For scheduling purposes, use 32-cycle issue rate.

## Output Layout (Column-Major)

Same 16x16 column-major layout as v_mfma_f32_16x16x32_bf16:

```
Lane L (0..63) has 4 AGPRs: a[k] = C[(L/16)*4 + k, L%16]   for k=0..3
```

## Operand Requirements

| Operand | Register | Count | Constraint |
|---------|----------|-------|------------|
| Src0 (A) | VGPRs | 8 | Must be VGPRs. **8 VGPRs** (2x the BF16 variant) |
| Src1 (B) | VGPRs | 8 | Must be VGPRs. **8 VGPRs** |
| Src2/Dst (C/D) | AGPRs | 4 | Accumulator input/output |

Source operands are read through cycle 11. Cannot overwrite source VGPRs until cycle 12.

---

## Co-Execution Window

| Cycle Range | Activity |
|-------------|----------|
| 0-7 | Reads A, B, D operands. **No co-execution.** |
| 8-11 | Co-exec: TEX, LDS. **VALU not available until cycle 12.** |
| 12-31 (or 12-47) | Full co-exec: TEX, LDS, ALU0, LD_SCALE. |
| 32+ | Can issue next MFMA. |

The ALU0 co-execution starts at cycle 12 (not cycle 8 as for BF16 MFMAs). This is because source reads extend through cycle 11. The co-execution window is 20-36 cycles depending on whether latency is 32 or 48.

---

## NOP Requirements

| Transition | Required Wait |
|------------|---------------|
| `s_waitcnt` -> this MFMA | **0 NOPs** |
| VALU write -> this MFMA (same src VGPR) | **2 NOPs** (s_nop 1 x 2) |
| This MFMA -> another MFMA (diff AGPR dest) | **0 NOPs** |
| Last MFMA -> `v_accvgpr_read_b32` | **64 NOPs** (s_nop 15 x 4) |
| `v_accvgpr_write_b32` -> this MFMA (same AGPR) | **1 NOP** (s_nop 0) |

## CBSZ / BLGP Encoding

CBSZ selects matrix A format. BLGP selects matrix B format.

| CBSZ[2:0] | A Format |
|-----------|----------|
| 0 | FP8 (E4M3) |
| 1 | BF8 (E5M2) |
| 2 | FP6 (E3M2) |
| 3 | FP6 (E2M3) |
| 4 | FP4 (E2M1) |

| BLGP[2:0] | B Format |
|-----------|----------|
| 0 | FP8 (E4M3) |
| 1 | BF8 (E5M2) |
| 2 | FP6 (E3M2) |
| 3 | FP6 (E2M3) |
| 4 | FP4 (E2M1) |

Common combinations:
- `cbsz:0 blgp:0` -- FP8 x FP8 (E4M3 x E4M3)
- `cbsz:0 blgp:1` -- FP8 x BF8 (E4M3 x E5M2)
- `cbsz:1 blgp:1` -- BF8 x BF8 (E5M2 x E5M2)

**FNUZ correction**: `tl.dot_scaled` uses OCP FP8 format. If data is in FNUZ format, apply 0.25x correction factor (2x per operand, so 0.5 * 0.5 = 0.25).

## Known Bugs / Gotchas

1. **8 VGPRs per source operand**: Double the register pressure of BF16 variants. Register allocation must account for 16 source VGPRs per MFMA.

2. **Source read extends to cycle 11**: Unlike BF16 MFMAs where source reads complete by cycle 7, this instruction reads through cycle 11. Cannot overwrite source VGPRs with ds_read until cycle 12.

3. **ALU0 co-exec delayed to cycle 12**: VALU instructions cannot co-execute during cycles 8-11. Only TEX and LDS co-execution available in that window.

4. **Same accum_offset/AGPR aliasing and drain bugs as all MFMA instructions.**

5. **v_cvt_scalef32_pk_f16_fp8 for dequant**: Use native conversion instructions for FP8-to-FP16 dequantization. E8M0 scale encoded as `(byte << 23)`.

## Use Cases

- **Persistent FWD/DGRAD grouped GEMM**: Single launch processes all 32 expert groups sequentially. Primary FP8 MFMA for MI355X grouped GEMM.
- **FP8 training**: Mixed-precision training with FP8 forward pass.
- **Critical upgrade path**: Switching from legacy `v_mfma_f32_16x16x32_fp8_bf8` (K=32, 16,384 FLOPs) to this instruction (K=128, 65,536 FLOPs) gives **1.67-1.76x speedup**. This is the single biggest grouped GEMM optimization.
