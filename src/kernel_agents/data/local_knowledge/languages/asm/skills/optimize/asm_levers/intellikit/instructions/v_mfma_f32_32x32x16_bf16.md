# v_mfma_f32_32x32x16_bf16

BF16 matrix fused multiply-add, 32x32 output tile, K=16. Larger tile variant producing 16 AGPRs of output per instruction. Used in FWD attention and optimized GEMM libraries' larger tile strategies. Same FLOPs as the 16x16x32 variant but with higher register pressure and longer latency.

---

## Quick Reference

| Field | Value |
|-------|-------|
| Opcode | `v_mfma_f32_32x32x16_bf16` |
| Tile Shape | 32 rows x 32 cols, K=16 |
| Input Type | BF16 (packed pairs in VGPRs) |
| Output Type | FP32 (accumulated in AGPRs) |
| Latency | ~32 cycles |
| Issue Rate | ~32 cycles |
| FLOPs | 32 * 32 * 16 * 2 = 32,768 |
| Measured CPI | 31.2 shader cycles (isa-bench, within 2% of spec) |

---

## Output Layout (Column-Major)

M (row) is derived from VGPRs, N (col) is derived from lanes. Empirically verified on MI355X.

```
Half h = l / 32         (0 or 1)
Lane l: N = l % 32      (column index, 0..31)

VGPR k (0..15): M = h*4 + (k%4) + (k/4)*8

  k=0: M = h*4 + 0      k=4: M = h*4 + 8
  k=1: M = h*4 + 1      k=5: M = h*4 + 9
  k=2: M = h*4 + 2      k=6: M = h*4 + 10
  k=3: M = h*4 + 3      k=7: M = h*4 + 11
  ...
```

16 AGPRs per instruction output. Swapping A/B operands (K=A, Q=B) makes row-max reduce across VGPRs (cheap `v_max3`) instead of across lanes (expensive bpermute).

## Operand Requirements

| Operand | Register | Count | Constraint |
|---------|----------|-------|------------|
| Src0 (A) | VGPRs | 4 | **Must be VGPRs, NOT AGPRs** |
| Src1 (B) | VGPRs | 4 | **Must be VGPRs, NOT AGPRs** |
| Src2/Dst (C/D) | AGPRs | 16 | Accumulator input/output |

Source VGPRs are latched at issue time. Same source-latching rules as 16x16x32.

---

## Co-Execution Window

| Cycle Range | Activity |
|-------------|----------|
| 0-7 | Reads A, B, D operands. **No co-execution.** |
| 8-31 | Free. Co-exec: TEX, LDS, ALU0, LD_SCALE. |
| 32+ | Can issue next MFMA. |

The 32-cycle latency provides a much larger co-execution window than the 16x16x32 variant (24 free cycles vs 8). This makes it more suitable for hiding long-latency memory operations but requires more careful scheduling to fill the window.

---

## NOP Requirements

Same hazard rules as v_mfma_f32_16x16x32_bf16:

| Transition | Required Wait | Consequence if Missed |
|------------|---------------|----------------------|
| `s_waitcnt` -> this MFMA | **0 NOPs** | No hazard |
| VALU write -> this MFMA (same src VGPR) | **2 NOPs** (s_nop 1 x 2) | MFMA reads stale VGPR |
| This MFMA -> another MFMA (diff AGPR dest) | **0 NOPs** | Issue rate is the only constraint |
| Last MFMA -> `v_accvgpr_read_b32` | **64 NOPs** (s_nop 15 x 4) | Non-deterministic NaN |
| `v_accvgpr_write_b32` -> this MFMA (same AGPR) | **1 NOP** (s_nop 0) | Accumulates into stale value |

XDL Write -> VALU read requires 7/11/19 NOPs depending on pass count (28/44/76 cycles). Conservative: 4x s_nop 15 for MFMA drain.

## Known Bugs / Gotchas

1. **16 AGPRs = 4x register pressure**: Each MFMA block uses 16 AGPRs vs 4 for the 16x16 variant. A 4x4 grid of 32x32 blocks needs 256 AGPRs, forcing occupancy=1.

2. **Zero-AGPR mode possible**: Some FWD attention kernels use v_mfma_f32_32x32x16_bf16 with ALL results stored in VGPRs (not AGPRs). This is possible on gfx950 where the VGPR and AGPR files are unified.

3. **Output layout is not trivially row-major**: The M=VGPR, N=lane mapping with the h*4+(k%4)+(k/4)*8 formula is non-obvious. Must be worked out empirically.

4. **Same MFMA drain disagreement as 16x16x32**: Use 4x s_nop 15 conservatively.

## CBSZ / BLGP Encoding

Not applicable to this opcode. CBSZ/BLGP are used only for f8f6f4 format selection.

## Use Cases

- **FWD attention**: Primary MFMA in flash attention. 16 MFMAs per loop iteration. Q*K^T and P*V both use this instruction.
- **Larger tile GEMM**: Used in 256x128, 256x208, 320x192 tile strategies for higher arithmetic intensity.
- **Row-max reduction optimization**: Swapping A/B operands makes softmax row-max reduce across VGPRs (cheap v_max3) instead of across lanes.

## 16x16x32 vs 32x32x16 Comparison

| Property | 16x16x32 | 32x32x16 |
|----------|----------|----------|
| FLOPs/instruction | 16,384 | 32,768 |
| Latency | 16 cycles | 32 cycles |
| AGPRs per block | 4 | 16 |
| Co-exec window | 8 cycles | 24 cycles |
| Measured CPI | 15.6 | 31.2 |
| FLOPs/cycle | 1,024 | 1,024 |
| Register pressure | Low | High |
| Use case | GEMM, fine scheduling | Attention, large tiles |

Both variants have identical compute density (FLOPs/cycle). The choice depends on register budget and scheduling constraints.
