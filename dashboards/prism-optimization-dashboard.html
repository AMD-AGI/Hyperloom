DFS Heuristic Scoring Function

score = (expected_gain_per_gpu / cost_minutes) × (1 − accuracy_risk) × (1 − crash_risk) × target_gap_multiplier

The orchestrator maintains a priority stack. After each action completes, all remaining candidates are re-scored and the highest-scored is popped next. This is DFS because each action can push sub-actions (e.g., PROFILE pushes GEAK candidates, BACKENDS pushes combination tests). Exploration is depth-first along the most promising branch, with backtracking when scores shift.

Score update rules: Gain >0% → boost similar actions by 1.5×. Gain ≤0% → reduce by 0.5×. After 2+ backend wins → push combined_test at sum×1.5. After kernel keep → push re-profile. After 2+ discards on vendor kernels → reduce all GEAK scores to ~0. When all scores <1.0 → proceed to sweep → report.

Accuracy Gate Protocol

Every action that modifies computation must pass: kernel micro-benchmark (torch.allclose, atol=1e-3) + E2E output check (compare with accuracy_reference.json). If accuracy fails → REVERT immediately, log crash_risk=1.0 to KB. Scheduling-only params (decode-steps, cuda-graph-max-bs) skip the gate.
