① 结论:两个加载 gap，被 framework-agent 诊断并修复

GLM-5.2 的 glm_moe_dsa 复用了 vLLM 的 deepseek_v2.py 代码路径,但有两个 ROCm/vLLM 0.22.0 未覆盖的加载缺口。EXPLORE 之前的 enablement 环节(coordinator 驱动的 framework specialist)在 baseline 无法启动时被触发,读源码、复现、写 git apply 补丁,依次修复两个 gap 直到模型完整 boot。
GAP #1 patch 001
qk_rope_head_dim 维度错乱
shape_mismatch @ weight loader
transformers GlmMoeDsaConfig.attribute_map 把 head_dim ↔ qk_rope_head_dim 弄反 → 读到 192 而非 64,MLA 权重切分越界。patch 001 检测到该 bug 并从 config.json 读回正确的 64。
GAP #2 patch 002
indexer.k_norm 权重缺失
weights not initialized from checkpoint
checkpoint 只为 21 个 'full' indexer 层提供 k_norm,但 vLLM 在全部 78 层实例化。patch 002 在 load_weights() 中让 57 个 'shared' 层从最近的 full 层复制 k_norm 并标记为已加载。
两个 gap 都发生在权重加载 / 模型构建期(不是 kernel 或 config 层),因此普通 EXPLORE 杠杆无法触及 —— 必须由能读源码、写 git apply 补丁的 framework specialist 处理。这正是 enablement 环节存在的意义。

② Enablement 环节的机制(coordinator 驱动的自修复闭环)

baseline 无法 boot 时,PRELUDE 进入一个「捕获失败日志 → 派发 specialist 撰写补丁 → integrate 应用+重启验证 → 判定 advanced / runnable」的闭环,一次修一个更深的 gap 并把补丁堆叠,直到模型完整启动。

③ 两个决定性补丁(specialist 自撰的源码改动)

patch 001  qk_rope_head_dim · vllm/model_executor/models/deepseek_v2.py
根因:transformers 的 GlmMoeDsaConfig.attribute_map 把 head_dim 与 qk_rope_head_dim 映射弄反,导致 vLLM 读到 192(实为 qk_nope_head_dim)而非正确的 64,MLA 权重切分 .narrow() 越界。
if config.model_type == "glm_moe_dsa":
# attribute_map bug: qk_rope==qk_nope==head_dim 时触发
+ if qk_rope_head_dim == qk_nope_head_dim == head_dim:
+ raw = json.load(open(f"{path}/config.json"))
+ qk_rope_head_dim = raw["qk_rope_head_dim"] # = 64
patch 002  k_norm 权重共享 · DeepseekV2Model.load_weights()
根因:checkpoint 只含 21 个 'full' 层的 indexer.k_norm(层 0,1,2,6,10,…,74);57 个 'shared' 层需在加载后从最近的 full 层复制。补丁使用 load_weights() 子模块作用域的正确 key(不含 model. 前缀)。
# 加载完成后,为 shared 层补齐 k_norm
+ for dst, src in shared_to_full.items():
+ w = f"layers.{dst}.self_attn.indexer.k_norm.weight"
+ b = f"layers.{dst}.self_attn.indexer.k_norm.bias"
+ params_dict[w].data.copy_(params_dict[srcW].data)
+ params_dict[b].data.copy_(params_dict[srcB].data)
+ loaded_params.add(w); loaded_params.add(b)
两个补丁作为 enablement_kept_patches 堆叠应用到 vLLM 源码树:patch 001 先修好 MLA 维度,patch 002 在其之上补齐 sparse-attention indexer 的 k_norm 权重,使 8-way TP 的 FP8 MoE 引擎完整 boot。

关键观察
  • 目标达成:optimizer 仅靠自身 framework specialist,把「根本无法 boot」的 glm_moe_dsa 修到可加载、可服务、可测(1148.74 tok/s)。全部补丁由 specialist 自撰,无人工代写。
